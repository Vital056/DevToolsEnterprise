# DevToolsEnterprise

Имя проекта в OpenViking и cognee: `devtoolsenterprise`
(`viking://resources/projects/devtoolsenterprise/`, набор cognee `devtoolsenterprise`).
Правила сохранения памяти проекта — в пользовательском `~/.claude/CLAUDE.md`.

Внешний отчёт для 1С:Предприятие 8.3.27+ (управляемые формы): изменения объекта в расширениях,
роли и права, выгрузка расширений в .cfe. Исходники — XML-выгрузка 2.20 в `src/`
(`src/DevToolsEnterprise.xml` и каталог `src/DevToolsEnterprise/`).

## Публичный репозиторий

Репозиторий публичный (GitHub `Vital056/DevToolsEnterprise`), а тестовые базы — из клиентских
проектов. Поэтому в коммиты не попадают:

- имена и синонимы клиентских расширений и объектов (в комментариях и примерах — типовые
  объекты, например `Справочник.Контрагенты`, `Реквизит.Комментарий`);
- пути к базам, пользователи и пароли: они только в `.v8-project.json` (в `.gitignore`);
- скриншоты без обработки: перед публикацией в `docs/images` имена расширений закрываются
  `tools\pixelate.ps1`.

## Тестовые базы

Своей базы у проекта нет: используются файловые базы соседних проектов в `C:\Claude\*\build\ib`.
Реестр — `.v8-project.json` (формат 1c-skills `/db-list`, образец `.v8-project.json.example`):

| id | алиасы | что в базе |
|---|---|---|
| `dogovor` (default) | `erp`, `договоры` | ERP 2.5 + CRM, расширения с заимствованиями, формами и кодом |
| `zup` | `зуп` | ЗУП 3, около 65 расширений |
| `kz` | `кз` | ERP 2.5 + CRM |

Базы чужие: в них ничего не записываем и расширения не меняем, только читаем. Конфигуратор
на них не запускаем (сборка идёт на пустой `build\stub-ib`), чтобы не блокировать соседние проекты.

## Команды

| Команда | Что делает |
|---|---|
| `scripts\build.bat` | собрать `build\DevToolsEnterprise.erf` и служебную `build\launcher\DevToolsLauncher.epf` |
| `scripts\test.bat [база]` | собрать и открыть отчёт в тестовой базе (по умолчанию `dogovor`) |
| `scripts\run-1c.bat -Base <база> [-OpenReport] [-URL …]` | открыть тестовую базу; `-OpenReport` — сразу с отчётом |
| `powershell -File tools\smoke-com.ps1 [-Base <база>] [-Object <полное имя>]` | проверка серверной части отчёта через COM, без интерфейса |
| `powershell -File tools\compare-cfe.ps1 -OutDir <каталог> [-Base <база>]` | сверить выгруженные вкладкой «Выгрузка расширений» .cfe с базой |
| `tools\ui.ps1 -Action list` / `-Action click -X -Y` / `-Shot <png>` | окна клиента 1С, щелчки и снимки экрана для проверки форм |
| `tools\pixelate.ps1 -Src -Dst -Crop x,y,w,h -Blur "x,y,w,h;…"` | обрезать скриншот и закрыть имена расширений |

`DevToolsLauncher` (исходники `tools/launcher`) подключает ERF через `ВнешниеОтчеты.Подключить`
и открывает его стартовую форму: путь к ERF передаётся параметром клиента `/C`. Открыть ERF
напрямую через `/Execute` нельзя — платформа открывает его как обработку с пустой формой.

`run-1c.ps1 -OpenReport` сам закрывает окно ошибки лицензирования CRM (Escape), окно входа
в Интернет-поддержку (крестиком, данные ИТС не вводить) и отвечает «Да» в предупреждении
безопасности — только для своей служебной обработки. Escape в предупреждении означает «Нет».
Окна узнаются по размерам при масштабе экрана 125%. Если RDP-сеанс заблокирован или свёрнут,
снимки экрана и щелчки не работают — проверяйте через `tools\smoke-com.ps1`.

## Проверка изменений

1. `scripts\build.bat` — сборка без ошибок.
2. `tools\smoke-com.ps1` на `dogovor` и `zup` — без FAIL.
3. Изменения форм и клиентского кода — в клиенте через `scripts\test.bat`.
4. Анализ кода — BSL Language Server (MCP `bsl-language-server` из `.mcp.json` или CLI,
   `C:\Tools\bsl-language-server\bsl-language-server.exe`).

Внешний отчёт работает в любой конфигурации, поэтому в коде только методы платформы:
без общих модулей БСП и объектов конкретной конфигурации.
